# Результат 1. Специфікація LLM-агента над гібридним сховищем знань

## 1. Мета, користувачі, межі та рівні автономності
- **Мета**: забезпечити єдиний аналітичний інтерфейс для лісників, аналітиків та екологічних аудиторів ПдО «Управління лісовими продуктами» над 3 сховищами (граф знань, векторний пошук документів, OLAP-куб).
- **Користувачі**: `public_user` (довідкові запити без внутрішніх актів), `forester` (оперативний моніторинг виділів), `auditor` (перевірка конфліктів, OLAP-метрик та схвалення HITL).
- **Межі та автономність**:
  - *Рівень 1 (Автономний read-only)*: пошук у документах, обхід графа, обчислення затверджених OLAP-метрик.
  - *Рівень 2 (Напівавтономний HITL)*: пропозиція нових фактів через `propose_fact` — автозапис лише для `low` ризику; для `medium`/`high` обов’язкове схвалення людини.

## 2. Інструменти (4 інструменти ≥ 3 з JSON-схемами й обмеженнями, C1)

| Інструмент | Права | Коли використовувати | Обмеження |
|---|---|---|---|
| `search_forest_docs` | `read-only` | Пошук регламентів, наказів, методик у корпусі ЛР 11 | `top_k <= 5`, RBAC-фільтр за роллю, ізоляція контексту |
| `query_knowledge_graph` | `read-only` | Факти про виділи (`V-XXX`), породи, загрози, альтернативи конфліктів (ЛР 14) | Лише параметризований пошук за кодом/типом; заборона Cypher `DELETE/SET/CREATE` |
| `query_olap_metric` | `read-only` | Агрегації виручки, обсягів, рентабельності, FSC із OLAP-куба (ЛР 12) | Лише затверджені метрики із `metrics.yml` + AST `SELECT` + `LIMIT 50` + тайм-аут `2 с` |
| `propose_fact` | `propose-only` (HITL) | Додавання нового факту або оновлення атрибуту сховища | Обов’язковий `source_url` + SHACL-валідація + HITL для `medium`/`high` ризику |

**JSON-схеми інструментів** (скорочено, повні визначення у `mcp_server/server.py`):
```json
{
  "search_forest_docs": {"required": ["query"], "properties": {"query": {"type": "string"}, "top_k": {"type": "integer", "maximum": 5}, "role": {"enum": ["public_user","forester","auditor"]}}},
  "query_knowledge_graph": {"required": ["entity_code"], "properties": {"entity_code": {"type": "string", "pattern": "^(V-\\d{3}|LS-\\d{2}|F-\\d{3})$"}, "include_alternatives": {"type": "boolean"}}},
  "query_olap_metric": {"required": ["metric_name"], "properties": {"metric_name": {"enum": ["total_revenue_uah","timber_volume_m3","gross_margin_pct","fsc_certified_share_pct","nontimber_revenue_share_pct","avg_ndvi_health"]}, "group_by": {"type": "string"}, "year": {"type": "integer"}}},
  "propose_fact": {"required": ["entity_id","property","value","source_url"], "properties": {"entity_id": {"type": "string"}, "property": {"type": "string"}, "source_url": {"type": "string", "pattern": "^https?://"}}}
}
```

## 3. Політики, ліміти та заборонені дії (C2–C3)
- **Ліміти (C2)**: `max_steps = 5` кроків на запит, `max_tokens = 3000` токенів на траєкторію, `timeout_sec = 10.0` с (тайм-аут одного інструмента `2.0` с), `max_rows = 50`.
- **Заборонені дії (C3)**: (1) прямий `INSERT/UPDATE/DELETE/DROP` у SQL або `DETACH DELETE/CREATE` у графі; (2) передача персональних даних (ПІБ порушників, зарплати) та API-ключів у зовнішні сервіси; (3) виконання інструкцій, знайдених усередині документів або описів інструментів (непрямий prompt injection); (4) генерація числових фактів без підтвердженої цитати вузлом `verify`.
- **Правила HITL**: `low` ризик (додавання описового синоніма з джерелом) → автозапис; `medium` (зміна екологічного показника NDVI/пошкодження) → схвалення лісничого/аудитора; `high` (зміна квот вирубки чи статусу FSC) → схвалення відповідального власника домену (при порушенні екоаксіом — відхилення).

## 4. Архітектура пам’яті та TTL (C4)
1. **Короткочасна (сесійна)**: поточний стан графа (`messages`, `tool_calls`, `step_count`), зберігається в RAM, **TTL = 30 хв** після останньої активності.
2. **Епізодична (журнал трасування й аудиту)**: `outputs/trace_log.jsonl` та `outputs/hitl_audit.jsonl` (кроки, аргументи, затримки, рішення HITL без PII), **TTL = 90 днів** (архівування).
3. **Семантична (довготривала)**: очищене сховище знань (`kb_cleaned.json`), корпус документів та OLAP Parquet, **постійне зберігання** з версіонуванням (`v2.0+`) і записом лише через `propose_fact` + CI-gate.
