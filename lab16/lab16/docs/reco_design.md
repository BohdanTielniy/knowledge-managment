# Результат 1. Проєктування рекомендаційного модуля (Domain Knowledge Hub)

## 1. Реалізовані підходи (C1, C3)
- **Popularity (baseline)**: ранжування за частотою взаємодій у `train` (без витоку з `test`).
- **Graph Paths (2-hop)**: підрахунок спільних вузлів у графі знань (`User → Forestry / Species / Threat → Item`).
- **Embeddings kNN**: косинусна схожість між усередненим векторним профілем користувача та вектором об’єкта.
- **Hybrid RRF**: `score = 0.55 / (60 + rank_graph) + 0.45 / (60 + rank_emb)` — поєднує графову пояснюваність і семантичне узагальнення.

## 2. Фільтри якості та прав доступу (C2)
Перед ранжуванням `filter_catalog()` відсіює: (1) неперевірені записи (`verified == False`, напр. `ITEM-25`); (2) застарілі документи (`updated_at < 2025-11-24`, напр. `ITEM-26`); (3) об’єкти з рівнем доступу вище ролі користувача (`sensitivity: restricted` приховано для `public_user` і `forester`, `internal` приховано для `public_user`).

## 3. Обмеження (≥ 3, C4)
1. **Фільтраційна бульбашка (Filter Bubble)**: надмірна вага історії лісництва звужує різноманітність міжрегіональних практик.
2. **Офлайн vs онлайн розрив**: `nDCG@10` на історичних кліках не гарантує реальної корисності в польових умовах без A/B-тесту.
3. **Залежність від повноти графа**: нові документи без прив’язки до IRI втрачають графовий сигнал і покладаються лише на embeddings.
4. **Синтетичні взаємодії**: журнал кліків 60 користувачів змодельовано детерміновано (`seed=42`) для відтворюваної офлайн-оцінки.
