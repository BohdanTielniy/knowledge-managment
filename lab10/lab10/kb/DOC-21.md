# Архітектура Domain Knowledge Hub: зв'язок онтології, Neo4j та векторного пошуку
Дата публікації: 2026-11-15 | Категорія: architecture | Доступ: internal

## Трирівнева архітектура сховища знань

Платформа Domain Knowledge Hub поєднує три комплементарні технології: формальну OWL/SHACL-онтологію (ЛР 6–8) для стандартизації понять і правил, графову базу Neo4j (ЛР 9) для багатокрокових запитів і GDS-аналізу та векторне сховище (ЛР 10) для семантичного пошуку по неструктурованих документах.

Кожен документ у векторному індексі пов'язаний через ідентифікатори виділів (V-012, V-102), лісництв (LS-01..LS-04) і процесів із вузлами графа Neo4j.

## Чому потрібен гібридний пошук BM25 + Dense + RRF

Чисто семантичний (dense) пошук добре розуміє перефразування та синоніми (наприклад, «сильне всихання ялин» ↔ «ураження короїдом»), але часто помиляється на точних кодах на кшталт ЛК-2026-047, V-102 чи R8.

Поєднання лексичного BM25 та векторного пошуку через Reciprocal Rank Fusion (RRF, k=60) із подальшим cross-encoder reranking забезпечує високу точність як для термінологічних, так і для змістових запитів.

## Підготовка до RAG-конвеєра (ЛР 11)

Результати оцінювання на золотому наборі (recall@5, recall@10, MRR, nDCG@10) визначають оптимальний ретрівер для наступної лабораторної роботи ЛР 11 (RAG).

Обов'язковою вимогою безпеки перед передачею контексту в LLM є метаданий pre-filter за sensitivity, датою та типом документа.
